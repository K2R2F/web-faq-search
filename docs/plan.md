# 企画書

## 1. 今回確認すること

会計年度任用職員制度の事務処理マニュアルを、Googleアカウントなしで検索・閲覧できるWebアプリとして公開する方針を採用するか確認する。

## 2. 目的

Google アカウントを持たない人も含めて、会計年度任用職員制度のマニュアルと Q&A をブラウザだけで検索できるようにする。

## 3. 推奨案

GitHub Pagesで公開する静的Webアプリとし、次の2機能を提供する。

1. マニュアルに収録されたQ&Aを、問番号・分類・質問文・回答文から検索する。
2. マニュアル本文を、単語・複数語・章から検索する。

第1段階では生成AIによる回答生成を行わず、原文と根拠位置を直接表示する。生成AIは第2段階の任意機能とし、検索で取得した根拠だけを用いて回答案を作る。

## 4. 提供価値

- マニュアルの該当箇所をすぐ探せる
- Q&A を質問ベースで引ける
- ログイン不要で共有しやすい
- 静的配信なので運用コストを抑えやすい

## 5. 想定利用者

- 事務局担当者
- 現場の閲覧者
- Googleアカウントを持たない閲覧者

## 6. MVPの成果物

- GitHub Pages で公開する静的 Web アプリ
- 検索対象データは事前生成した JSON
- ブラウザ内で検索・絞り込み・本文表示を行う
- アカウント登録、質問送信、閲覧履歴保存は行わない

## 7. スコープ

### 今回実装する範囲

- Q&A／本文／全体の検索切替
- Q&A分類・章による絞り込み
- 検索語のハイライト
- 問番号、章節、原文スニペット、前後文脈の表示
- モバイル対応とキーボード操作
- Markdownから検索用JSONを生成する開発用スクリプト
- GitHub Pages向けのビルド・公開設定

### 今回実装しない範囲

- Gemini APIによる回答生成
- ログイン、利用者管理、質問履歴
- 個別自治体の条例・規則を踏まえた判断
- 非公開資料の検索
- 原PDFのページ番号復元

## 8. 開発方針

1. まず検索 UI と索引データの仕様を固める。
2. その後に、マニュアル Markdown から索引を作る変換処理を実装する。
3. 最後に、GitHub Pages へ載せる静的フロントエンドを実装する。

## 9. 段階計画

1. 企画・仕様の承認
2. Markdown解析と独立Q&A見出し112件の分割検証
3. 検索索引JSON生成
4. 静的Web UI実装
5. 検索精度・アクセシビリティ・公開データ確認
6. 独立Gitリポジトリ化とGitHub Pages公開
7. 必要性が確認できた場合のみ、生成AI連携を別プロジェクトとして設計

## 10. 決定済み事項

- 対象マニュアルは総務省Webサイトで公開されている公的資料をMD化したものであり、公開リポジトリへ収録してよい。
- 第1段階はGitHub Pages上の静的検索アプリとする。
- 生成AI連携は第2段階として分離する。

## 11. 要確認事項

- 正式な原典URL、版数、改訂日を画面に表示できるか
- 公開先を個人アカウント、組織アカウントのどちらにするか
- 第1段階完成後、生成AI連携の検討へ進むか

## 12. 完了判定

- 原MDで設問見出しとして抽出できる112件のQ&Aが欠落・混在せず表示される
- 代表的な表記ゆれを含む検索テストに合格する
- 検索結果から根拠となる原文へ到達できる
- 外部API、Cookie、個人情報収集なしで動作する
- GitHub Pagesのサブパスで表示・検索できる
